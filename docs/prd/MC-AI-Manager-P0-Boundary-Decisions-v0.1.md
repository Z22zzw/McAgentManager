> 文档版本：v0.1

> 适用阶段：M0 技术探针、M1 部署闭环、M2 基础管理 Demo  
> 上游文档：[`MC-AI-Manager-PRD-v0.1.md`](MC-AI-Manager-PRD-v0.1.md)

## 1. 文档目的

本文件把 PRD 中的方向性描述转化为可研发、可测试、可拒绝的 P0 边界。矩阵外能力可以被识别和解释，但不纳入 P0 自动完成承诺。

边界遵循四条规则：

1. 对支持范围内输入形成稳定闭环。
2. 对范围外输入尽早停止，并说明原因和下一步。
3. Agent 拥有完成任务所需能力，但不可信内容不能获得执行权。
4. 所有“成功”必须由实际状态验证。

## 3. 部署与运行环境边界

### BD-ENV-01 支持环境

P0 正式支持：

- Ubuntu Server 24.04 LTS。
- x86_64 / amd64。
- systemd 可用。
- 单台主机运行 MCSManager、DeepSeek Harness、MC 操作网关和 MC 实例。
- 实例和临时目录位于本地 ext4 或 xfs 文件系统，支持常规 Linux 权限、真实路径解析和文件锁。
- 部署人员拥有 sudo/root 权限完成初装。

### BD-ENV-02 不承诺环境

P0 不承诺：

- Windows、macOS。
- ARM64、RISC-V。
- Ubuntu 22.04、Debian、CentOS、Rocky、Alpine。
- Kubernetes、多节点或跨主机迁移。
- Docker Compose 作为主发布方式。
- NFS、SMB、对象存储上的实例工作目录。
- 多租户共享主机。

范围外环境可以由技术人员自行适配，但不计入 P0 成功率和缺陷 SLA。

### BD-ENV-03 默认目录

```text
/home/mc-agent/
├── uploads/
├── workspaces/
├── backups/
├── generated/
├── tasks/
└── audit/
```

不得把整个 `/home` 作为 Agent 默认工作区。系统级任务可以访问必要的工作区外目标，但需要单独标记和审计。

### BD-ENV-04 控制面与游戏进程隔离

上传的服务端 JAR、模组和插件属于不可信可执行代码。P0 必须隔离控制面权限与游戏进程权限：

- DeepSeek Harness 和操作网关属于控制面；只有网关的固定主机动作可以获得 sudo/root 能力。
- MCSManager daemon 与 MC 实例进程使用专用低权限账号 `mc-runner`，不得以 root 运行。
- `mc-runner` 无 sudo 权限，不能读取模型密钥、MCSManager 管理凭证、审计写入凭证或其他系统用户主目录。
- `mc-runner` 只拥有实例工作区、必要日志和运行时 Java 的读取/执行权限。
- 操作网关通过明确的服务接口管理文件与实例，不把自身凭证写入实例环境变量。
- 一个实例中的恶意模组仍可能读取该账号可访问的其他实例；P0 将此列为单租户受信任内容风险。每实例 OS 用户或容器隔离属于后续强化项。
- 环境自检若发现 MCSManager/MC 子进程以 root 运行，阻止上传内容的首次启动。

## 4. MCSManager 边界

### BD-MCS-01 版本

- 产品兼容策略面向 `v10.18.x` 版本线，但只有进入 `certifiedVersions` 清单的补丁版本允许写操作。
- 首个认证版本和开发/CI 契约基准：`v10.18.3`。
- 其他 `v10.18.x` 首次接入时只读检测；完整契约套件通过并保存报告后，才能加入认证清单。
- 检测到未认证版本时进入“版本待认证”状态：允许环境检查和人工高级处理，不执行自动写操作。
- 版本认证至少覆盖 API schema、认证、实例状态、创建、启停、日志、删除、错误、超时和高级入口。

### BD-MCS-02 P0 API 能力

必须通过契约测试固定：

- 认证与会话可用性。
- 实例列表和详情读取。
- 实例创建。
- 实例启动、正常停止、重启或目标状态控制。
- 实例状态和进程事实读取。
- 控制台日志读取或日志流。
- 实例配置读取与有限修改。
- 文件管理所需能力，或由 MC 操作网关替代。
- 实例删除或解除注册。
- 对应实例的高级管理深链能力。

### BD-MCS-03 事实优先级

1. MCSManager 实例定义和生命周期状态。
2. 主机进程与端口事实。
3. 服务端就绪日志或协议探测。
4. Agent 推断。
5. 对话历史。

低优先级信息不能覆盖更高优先级事实。

### BD-MCS-04 高级入口

- P0 使用新标签跳转，不使用 iframe。
- 不在 URL 中携带长期管理员 Token。
- 无安全短期会话时，用户独立登录 MCSManager。
- 返回后刷新实例状态、配置摘要和工作目录元信息。
- 发现外部修改时，相关未完成任务进入重新核对。

## 5. Minecraft 与服务端边界

### BD-MC-01 版本

P0 仅对以下版本形成自动部署承诺：

- Minecraft Java Edition 1.20.1。
- Minecraft Java Edition 1.21.1。

其他版本可以识别为“暂不在自动支持范围”，不得低置信度试运行。

### BD-MC-02 核心映射

| MC 版本 | P0 核心 |
|---|---|
| 1.20.1 | Vanilla、Paper、Fabric、Forge |
| 1.21.1 | Vanilla、Paper、Fabric、NeoForge |

为控制样本数量：

- P0 不承诺 1.20.1 NeoForge。
- P0 不承诺 1.21.1 Forge。
- Purpur 可识别为 Paper 兼容族，但不纳入正式成功率。
- Mohist、Arclight、CatServer、Sponge、Bukkit/Spigot 构建链不纳入 P0。
- Bedrock、BDS、PocketMine、Nukkit 不纳入 P0。
- Velocity、Waterfall、BungeeCord 等代理不纳入 P0。

### BD-MC-03 输入形态

支持：

- 一个 ZIP 文件。
- ZIP 解压后是完整、可直接运行的服务端目录。
- 可以已有世界、模组、插件和配置，但必须符合对应核心结构。
- Fabric ZIP 包含可运行启动 JAR 和必要 libraries。
- Forge/NeoForge ZIP 包含安装完成后的 `libraries`、参数文件和已识别启动模板。

不支持自动闭环：

- 客户端整合包。
- 仅世界存档。
- 官方/第三方安装器本体。
- 需要先运行安装器下载服务端依赖的包。
- 需要 CurseForge、Modrinth 或其他平台 API 转换的包。
- RAR、7z、tar、tar.gz。
- 依赖任意自定义安装脚本才能完成安装的 ZIP。

### BD-MC-04 启动入口

- Vanilla/Paper：只接受 Golden Sample manifest 中已登记的服务端 JAR 身份与入口规则，生成受控 Java 启动命令。
- Fabric：识别固定 Loader/Launcher 组合、入口 JAR 和 libraries，生成受控启动命令。
- Forge 1.20.1：必须且只能匹配 `libraries/net/minecraftforge/forge/1.20.1-47.4.23/unix_args.txt` 这一认证布局。
- NeoForge 1.21.1：必须且只能匹配 `libraries/net/neoforged/neoforge/21.1.249/unix_args.txt` 这一认证布局。
- 每个认证核心版本登记官方安装产物的参数文件 SHA-256；上传包的核心参数文件不一致时拒绝自动启动。
- 不直接执行 ZIP 内任意 `run.sh`、`start.sh`、`.bat` 或二进制文件。
- `user_jvm_args.txt` 不原样执行：仅解析 `-Xms`、`-Xmx` 和项目白名单 GC 参数，内存值受主机预算限制；其他参数忽略并在部署预览中列出。
- 禁止来自上传包的 `-javaagent`、`-agentlib`、`-agentpath`、嵌套 `@argfile`、工作区外路径和命令执行型 JVM 参数。
- 同时存在多个核心版本目录、参数文件缺失/哈希不符、引用文件不存在或布局无法唯一判断时，分类为 `ambiguous-or-modified-launcher` 并停止自动部署。

## 6. Java 边界

### BD-JAVA-01 版本映射

| MC 版本 | P0 Java |
|---|---|
| 1.20.1 | Java 17 |
| 1.21.1 | Java 21 |

### BD-JAVA-02 自动安装

用户已确认缺少 Java 时由 Agent 自动安装。P0 收敛为：

- 只从 Ubuntu 24.04 已配置且签名有效的官方 APT 软件源安装。
- 只安装 `openjdk-17-jre-headless` 和 `openjdk-21-jre-headless`。
- 操作网关必须预配置无交互、最小范围授权；普通 Agent/`mc-runner` 不直接拥有 sudo。
- 固定动作为 `apt-get install --no-install-recommends <approved-package>`；P0 运行期不自动执行 `apt update`、`upgrade`、`autoremove`、`--fix-broken` 或更换软件源。
- 不使用 `curl | sh`、第三方 PPA、自定义镜像或 ZIP 二进制包。
- 安装前检查候选包、仓库签名状态、网络、磁盘、`dpkg` 状态和 APT 锁。
- APT 锁最多等待 120 秒；持续占用时停止，不强杀其他包管理进程。
- `dpkg` 处于未完成/需修复状态时停止并交给部署人员处理。
- 安装命令属于主机级操作，记录候选包版本、来源、任务和结果。
- 安装后解析包文件清单确定 Java 绝对路径，执行 `java -version` 和对应 MC 最小启动预检。
- 安装中断后先检查 dpkg/包状态，不盲目重复安装。
- 安装失败时停止部署，不自动更换软件源。
- 不自动卸载、升级用户已有 Java，也不修改系统全局默认 Java。

### BD-JAVA-03 运行时选择

每个实例记录 Java 可执行文件绝对路径，不依赖全局 `PATH` 或默认 `java` 指向。

## 7. 上传与安全解压边界

### BD-ZIP-01 P0 默认限额

| 项目 | P0 默认值 |
|---|---:|
| 单个上传 ZIP | 4 GiB |
| 预估解压总量 | 24 GiB |
| 单个解压文件 | 8 GiB |
| 文件/目录条目数 | 100,000 |
| 目录深度 | 32 层 |
| 单路径长度 | 1,024 字节 |
| 最大压缩比 | 200:1 |
| 嵌套压缩包 | 作为普通文件，不递归解压 |

限额应支持部署人员配置，但修改后的环境不计入默认回归结果。

### BD-ZIP-02 磁盘预算

允许开始解压需要满足：

```text
峰值预算 = ZIP 大小 + 预估解压量 + Java 安装预留 + 安全余量
安全余量 = max(5 GiB, 文件系统容量的 10%)
当前可用空间 >= 峰值预算
```

Java 已安装时安装预留为 0，缺少 Java 时预留 1 GiB。无法可靠预估时按 24 GiB 解压上限计算。解压过程中持续监测磁盘；剩余空间低于安全余量时停止扩大占用并清理本任务隔离目录。ZIP 压缩比同时按单条目和全包计算，任一超过 200:1 都拒绝。

### BD-ZIP-03 拒绝项

- 绝对路径和 `..` 路径穿越。
- 解析后逃出任务隔离目录的路径。
- 软链接、硬链接、设备文件、FIFO。
- 重复冲突路径和大小写冲突。
- NUL 字符和异常路径编码。
- 超过限额的文件数、大小、深度、压缩比。
- 解压前元数据与实际写入量明显不一致。

## 8. 身份、网络与使用模式边界

### BD-AUTH-01 身份

- 单租户。
- 一个初始管理员账号。
- 所有写操作记录操作者。
- 不支持访客、玩家自助账号、多个管理员和 RBAC。
- 不允许匿名访问管理页面和 API。

### BD-NET-01 网络责任

产品 P0 验证：

- 实例进程状态。
- 服务端就绪信号。
- 本机目标端口监听。

产品 P0 不承诺：

- NAT/端口映射正确。
- 云安全组和防火墙正确。
- 域名、SRV 记录或公网线路可用。
- 外网玩家一定可连接。

这些属于部署人员负责的公网部署边界。页面必须明确显示“本机已就绪 / 外网未验证”。

### BD-NET-02 端口分配

- 部署人员配置一个 P0 测试/实例端口池，默认候选范围 `25565–25665`。
- 任务服务在检查本机监听状态后对候选端口建立持久化租约，避免并发任务选择同一端口。
- 端口写入实例配置后，以实际进程绑定结果为准；检查时空闲不等于启动后成功。
- 绑定失败最多重新选择 2 次；仍失败则停止并展示证据。
- 已有实例端口不自动修改。

### BD-NET-03 登录模式

- 创建新实例时默认选中“允许离线登录”，对应目标配置 `online-mode=false`。
- 用户必须在卡片中提交该选择，系统不得静默采用。
- 卡片说明名称冒用、OP、白名单和权限插件风险，并记录问题 ID、文案版本、选择和操作者。
- 用户选择优先于上传 ZIP 中的 `server.properties`；写入前展示差异，写入后回读验证。
- 实例主页持续显示“离线登录”或“正版验证”状态，并与实际配置回读值一致。
- 现有 MCSManager 实例只读取当前配置，不自动更改。

### BD-EULA-01 生命周期

P0 固定顺序为：

```text
上传 → 隔离解压 → 识别与预检 → 登录方式选择 → EULA 确认
→ 在隔离工作目录原子写入并回读 eula.txt → 注册 MCSManager 实例 → 首次启动
```

- “工作目录创建”不等于“MCSManager 实例创建”。
- 用户未确认时可以暂存隔离工作目录，但不得注册实例、写入 `eula=true` 或启动。
- ZIP 内已有 `eula=true` 只作为检测事实，不能替代当前用户确认。
- 确认记录包含 EULA 官方 URL、展示文案版本、操作者、任务、目标工作目录和时间。
- 写入必须使用固定相对路径 `eula.txt`，原子替换后回读验证。
- 确认过期、目标核心/目录改变或恢复时无法证明写入结果，必须重新核对或确认。

## 9. Agent 权限和执行边界

### BD-AGENT-01 权限目标

Agent 能完成 P0 合理任务，包括：

- MCSManager 实例管理。
- 专用目录文件管理。
- Java 17/21 自动安装。
- 受控命令执行。
- 进程、端口、磁盘和日志诊断。
- 必要的系统级读取和修改。

### BD-AGENT-02 执行约束

- 所有写操作通过 MC 操作网关。
- 操作绑定任务 ID、目标实例、风险级别和幂等键。
- ZIP、日志、README、玩家聊天和网页内容均为不可信数据。
- 不可信数据不能改变工具范围、目标路径、确认要求和网络目的地。
- Shell 命令必须由受控动作模板生成；模型不能把不可信文本直接拼入命令。
- 结果必须经过事实验证。

### BD-AGENT-03 模型不可用

模型不可用时仍允许：

- 服务器主页状态查看。
- 已存在实例的启动、停止和重启。
- 操作记录查看。
- 已经确定并获授权、且不再需要新模型决策的任务步骤继续执行。

不得自动生成新修复方案或跨越新的确认节点。

## 10. 数据破坏与磁盘边界

### BD-DELETE-01 不强制备份

磁盘不足时，删除实例或数据不强制创建备份。系统需要明确告诉用户是否可以恢复。

### BD-DELETE-02 清理顺序

1. 不完整上传。
2. 失败解压临时目录。
3. 可再生成安装缓存。
4. 超过保留期的日志。
5. 用户明确选择的备份归档。
6. 用户明确指定的实例和世界。

系统不能仅因为前四类空间不足就自动升级到实例删除。

### BD-DELETE-03 永久删除条件

- 绑定不可变实例 ID。
- 生成并展示服务端删除清单。
- 检查共享目录、挂载点和软链接。
- 展示运行状态、在线玩家、最近备份和恢复能力。
- 正常停止并验证进程退出；强制终止需要独立确认。
- 要求输入完整实例名称。
- 确认绑定单一 operation ID，默认 5 分钟有效；目标状态或删除清单变化时立即失效。
- 删除后验证 MCSManager 定义和目标目录状态，并重新测量磁盘。
- 中断后进入“需要核对”，不得盲目重放删除。

## 12. P0 非目标

- 任意版本和任意整合包的一键部署。
- 客户端整合包自动转服务端。
- Bedrock 服务端。
- 代理网络和多服群组。
- 多租户、多管理员、计费和商业运营能力。
- 自动安装模组、插件或整合包平台内容。
- 自动性能调优。
- 完整备份回档。
- KubeJS 自动开发。
- 公网网络自动配置。
- 任意 Linux 发行版支持。

## 13. 决策变更规则

边界冻结后，任何扩大支持范围的需求必须：

1. 更新本决策记录。
2. 更新支持矩阵。
3. 增加 Golden Sample。
4. 增加 BDD 场景和 TDD/契约测试。
5. 重新评估上传、安全、Java 和任务恢复预算。

只修改产品文案而不增加样本和测试，不视为已支持。
