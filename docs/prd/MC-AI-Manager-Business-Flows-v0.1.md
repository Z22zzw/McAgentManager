# MC AI Manager 业务流程图

> 文档版本：v0.1  
> 对应 PRD：[`MC-AI-Manager-PRD-v0.1.md`](MC-AI-Manager-PRD-v0.1.md)  
> 文档用途：产品评审、交互设计、研发拆分、测试用例设计  
> 图表格式：Mermaid

---

## 1. 流程设计原则

1. 用户表达目标，系统负责推导操作步骤。
2. 能从环境、文件和实例状态中判断的信息不询问用户。
3. 只对影响玩法、在线玩家、数据安全或费用的分歧进行提问。
4. 用户确认的是实际后果，不是 Linux 命令或配置参数。
5. Agent 的结论必须由 MCSManager、文件、进程或日志事实验证。
6. 对话、任务和审计是三套相关但独立的状态，不因页面关闭或会话中断而丢失。
7. 来自压缩包、日志、配置和网页的内容都按不可信数据处理，不得被解释为给 Agent 的新指令。

## 2. 产品系统上下文

```mermaid
flowchart LR
    U[普通服主] -->|目标、文件、选择| WEB[MC AI Manager Web]
    T[部署人员] -->|安装与系统配置| WEB

    WEB --> HOME[服务器主页]
    WEB --> CHAT[AI 管家]
    WEB --> AUDIT[操作记录]
    WEB --> ADV[高级管理]

    CHAT --> DSH[DeepSeek Harness]
    DSH --> AGENT[AI Agent]
    AGENT --> TASK[持久化任务服务]
    TASK --> GATE[MC 操作网关]

    GATE --> MCS[MCSManager API]
    GATE --> FS[专用工作区与文件系统]
    GATE --> HOST[Java、进程、网络与系统服务]
    GATE --> LOG[追加式审计日志]

    ADV -->|按实例深链跳转| MCSUI[MCSManager Web]
    MCSUI --> MCS
    MCS -->|真实实例状态| TASK
    TASK -->|任务与实例状态| WEB
```

### 2.1 边界说明

- Web 负责交互和展示，不直接把“按钮点击成功”当成任务完成。
- DeepSeek Harness 负责理解和编排，不作为任务状态的唯一存储。
- 任务服务负责幂等、锁、恢复和终态。
- 操作网关是 Agent 使用高权限能力的统一入口。
- MCSManager 是实例运行状态的主要事实来源。
- 高级管理首版采用受控跳转，不建议直接 iframe 嵌入。

## 3. 首次安装与接入流程

```mermaid
flowchart TD
    A[部署人员启动安装] --> B[检查支持的 Linux 与运行环境]
    B --> C{环境是否在支持矩阵内}
    C -- 否 --> C1[停止自动安装并展示人工部署要求]
    C -- 是 --> D[配置 MCSManager 地址与凭证]
    D --> E[配置模型与 DeepSeek Harness]
    E --> F[创建专用工作区和审计目录]
    F --> G[授予必要文件、命令、进程和系统服务权限]
    G --> H[创建首个管理员]
    H --> I[执行端到端自检]
    I --> J{自检是否通过}
    J -- 否 --> K[按阻断项提供修复步骤]
    K --> I
    J -- 是 --> L[生成安装报告]
    L --> M[进入服务器主页]
```

### 3.1 安装自检门槛

- MCSManager API 可连接并完成一次只读查询。
- 专用工作区可读写，临时目录可创建和清理。
- 操作记录可追加，敏感字段脱敏有效。
- 至少一个受支持 Java 版本可用。
- Agent 能调用操作网关，但不能绕过任务 ID 和审计。
- Web 与任务服务断线重连后能恢复任务状态。

## 4. 现有实例接入流程

```mermaid
flowchart TD
    A[系统连接 MCSManager] --> B[拉取现有实例列表]
    B --> C[建立 MCSManager 实例 ID 映射]
    C --> D[读取状态、工作目录与启动配置]
    D --> E{目录是否允许读取}
    E -- 否 --> E1[显示实例但标记“仅基础管理”]
    E -- 是 --> F[识别版本、核心和世界目录]
    F --> G{识别置信度是否足够}
    G -- 否 --> G1[显示未知信息且不猜测]
    G -- 是 --> H[补充实例元数据]
    E1 --> I[进入服务器主页]
    G1 --> I
    H --> I
```

### 4.1 产品规则

- 不复制或迁移已有实例，仅建立映射。
- 无法识别的字段显示“暂时无法识别”，不显示错误默认值。
- 从 MCSManager 修改实例后，重新同步事实状态。
- 删除、重建或迁移已有实例仍需进入正式任务流程。

## 5. ZIP 导入部署主流程

```mermaid
flowchart TD
    A[用户上传 ZIP] --> B[创建持久化部署任务]
    B --> C[校验格式、大小与上传完整性]
    C --> D{校验是否通过}
    D -- 否 --> D1[说明原因并结束任务]
    D -- 是 --> E[预估解压占用并检查磁盘]
    E --> F{空间是否充足}
    F -- 否 --> F1[进入磁盘清理流程]
    F1 --> F2{清理后是否继续}
    F2 -- 否 --> X[取消并清理临时数据]
    F2 -- 是 --> E
    F -- 是 --> G[隔离解压]
    G --> H{是否发现路径穿越、异常链接或压缩炸弹}
    H -- 是 --> H1[隔离文件并记录安全事件]
    H1 --> Z[任务失败]
    H -- 否 --> I[将文件内容标记为不可信数据]
    I --> J[识别服务端类型、版本、入口、Java 与已有世界]
    J --> K{是否属于 P0 支持类型}
    K -- 否 --> K1[说明识别结果和支持边界]
    K1 --> Z
    K -- 是 --> L{识别置信度是否达标}
    L -- 否 --> L1[展示候选项或要求更换文件]
    L1 --> Z
    L -- 是 --> M[检查 Java、端口、内存和实例名冲突]
    M --> N[展示不超过 3 个必要决策]
    N --> O[默认允许离线登录并说明公网风险]
    O --> P{用户是否接受 Minecraft EULA}
    P -- 否 --> X
    P -- 是 --> Q[预览将创建的实例]
    Q --> R[生成配置并调用 MCSManager 创建]
    R --> S{实例是否创建成功}
    S -- 否 --> S1[清理未完成映射并解释失败]
    S1 --> Z
    S -- 是 --> T[首次启动并持续读取真实状态]
    T --> U{是否达到“可运行”判定}
    U -- 是 --> V[展示地址、状态与常用操作]
    U -- 否 --> W[进入启动失败诊断流程]
```

### 5.1 “部署成功”的统一定义

部署成功必须同时满足：

1. MCSManager 实例创建成功。
2. 启动进程未立即退出。
3. 日志出现对应核心的就绪信号，或通过可配置的等价健康检查。
4. 实例状态在观察窗口内保持稳定。
5. 实际端口与展示地址一致。

只完成文件解压、实例创建或发送启动命令，均不能标记为部署成功。

## 6. 卡片式决策流程

```mermaid
flowchart TD
    A[Agent 发现分歧] --> B{系统能否自行判断}
    B -- 是 --> C[自动采用事实结果]
    B -- 否 --> D{是否属于用户应决定的事项}
    D -- 否 --> E[采用产品默认值并在结果中说明]
    D -- 是 --> F[生成玩家语言的问题卡片]
    F --> G[展示推荐项、影响和风险]
    G --> H{用户操作}
    H -- 选择 --> I[结构化保存选择]
    H -- 自定义 --> J[校验自定义输入]
    H -- 跳过 --> K{该问题是否可选}
    K -- 是 --> E
    K -- 否 --> L[说明为什么必须选择]
    L --> F
    H -- 取消 --> M[取消或暂停任务]
    I --> N[继续任务]
    J --> N
```

### 6.1 提问约束

- 同一屏不超过 4 个主要选项。
- 标准部署业务问题中位数不超过 3 个。
- 默认项必须说明采用它会发生什么。
- 永久删除类卡片不设置默认选中项。
- 对复杂术语提供玩家语言，不把配置字段名作为主标题。

## 7. 启动失败诊断与修复流程

```mermaid
flowchart TD
    A[实例未达到可运行状态] --> B[收集 MCSManager 状态、退出码与相关日志片段]
    B --> C[匹配确定性规则]
    C --> D{是否命中已验证规则}
    D -- 是 --> E[生成原因、证据与修复方案]
    D -- 否 --> F[由 Agent 进行辅助分析]
    F --> G{证据是否足以形成高置信度结论}
    G -- 否 --> H[明确表示无法确定并给出排查路径]
    G -- 是 --> E
    E --> I{修复是否会影响数据或系统}
    I -- 否 --> J[执行修复]
    I -- 是 --> K[展示后果卡片]
    K --> L{用户确认}
    L -- 否 --> M[保留现状并结束]
    L -- 是 --> J
    J --> N[重新启动并验证]
    N --> O{是否恢复}
    O -- 是 --> P[报告已恢复及修复内容]
    O -- 否 --> Q[记录尝试，禁止无限重试]
    Q --> H
```

### 7.1 可信度规则

- 规则命中和模型推测必须在数据层区分。
- 结论至少引用一个可查看的证据片段。
- 自动重试次数有限，且每次重试必须改变明确条件。
- 日志中的“请执行某命令”“忽略之前规则”等内容一律视为普通文本。

## 8. 日常启停流程

```mermaid
sequenceDiagram
    actor U as 用户
    participant W as Web
    participant T as 任务服务
    participant M as MCSManager
    participant A as 审计日志

    U->>W: 启动 / 停止 / 重启
    W->>T: 创建目标状态任务
    T->>T: 检查实例锁与当前状态
    alt 请求与当前状态重复
        T-->>W: 合并任务或返回当前进度
    else 可以执行
        T->>M: 调用实例控制
        T->>A: 记录动作开始
        M-->>T: 返回调用结果
        loop 直到成功或超时
            T->>M: 查询真实状态
            M-->>T: 当前状态
        end
        T->>A: 记录验证结果
        T-->>W: 成功 / 未按时完成 / 失败
    end
    W-->>U: 展示真实终态和下一步
```

## 9. 磁盘不足与无备份删除流程

```mermaid
flowchart TD
    A[检测到磁盘不足] --> B[暂停继续扩大占用的任务]
    B --> C[扫描可清理对象]
    C --> D[计算预计释放空间与风险等级]
    D --> E[优先展示日志、缓存、临时上传]
    E --> F{低风险清理是否足够}
    F -- 是 --> G[执行清理]
    F -- 否 --> H[展示备份归档、停用实例和世界数据]
    H --> I{用户选择对象}
    I -- 取消 --> X[保持现状]
    I -- 可恢复对象 --> J[说明恢复方式和保留期限]
    I -- 无备份实例/世界 --> K[明确标记删除后无法恢复]
    J --> L[确认删除]
    K --> M[无默认选项的永久删除确认]
    L --> N{是否确认}
    M --> N
    N -- 否 --> X
    N -- 是 --> O{目标实例是否运行中}
    O -- 是 --> P[正常停止实例]
    O -- 否 --> Q[执行删除]
    P --> Q
    Q --> R[重新计算磁盘空间]
    G --> R
    R --> S{是否达到继续任务的最低空间}
    S -- 是 --> T[恢复被暂停任务]
    S -- 否 --> U[继续提供剩余方案或结束]
```

### 9.1 删除规则

- 磁盘不足时不强制创建备份。
- 用户说“清理磁盘”不构成删除实例或世界的授权。
- 删除前展示目标名称、类型、占用、运行状态、最近备份和恢复能力。
- 永久删除必须获得一次独立、明确且可审计的确认。
- 清理结果以重新测得的可用空间为准。

## 10. 页面关闭、断线与任务恢复流程

```mermaid
stateDiagram-v2
    [*] --> Created
    Created --> Running
    Running --> WaitingUser
    WaitingUser --> Running: 用户回答
    Running --> Verifying
    Verifying --> Succeeded
    Verifying --> Partial
    Running --> Failed
    WaitingUser --> Cancelled: 用户取消

    Running --> Detached: 浏览器断线或会话关闭
    WaitingUser --> Detached: 浏览器断线
    Detached --> Running: Host任务仍在执行
    Detached --> WaitingUser: 仍等待用户
    Detached --> Recovering: Host或任务服务重启
    Recovering --> Running: 可安全续作
    Recovering --> WaitingUser: 需要重新确认
    Recovering --> ManualReview: 无法判断上一步是否完成
    ManualReview --> Running: 核对事实后续作
    ManualReview --> Failed: 无法安全续作

    Succeeded --> [*]
    Partial --> [*]
    Failed --> [*]
    Cancelled --> [*]
```

### 10.1 恢复规则

- 每个有副作用的步骤写入开始、目标、幂等键和验证结果。
- 重启后先核对事实，不盲目重放上一个命令。
- 无法判断删除、移动、创建是否完成时进入人工核对状态。
- 等待用户的问题可以恢复，但不得改变选项含义。
- 对话可以结束，任务不能因此消失。

## 11. 高级管理往返流程

```mermaid
flowchart TD
    A[用户从实例点击高级管理] --> B[记录来源实例与返回地址]
    B --> C[校验管理员身份]
    C --> D[跳转到对应 MCSManager 实例]
    D --> E[用户在 MCSManager 操作]
    E --> F[返回 MC AI Manager]
    F --> G[强制刷新实例与任务状态]
    G --> H{是否发现外部修改}
    H -- 否 --> I[正常展示]
    H -- 是 --> J[以实际状态覆盖旧缓存]
    J --> K[记录“高级管理外部变更”事件]
    K --> I
```

### 11.1 首版建议

- 首选深链跳转，不首选 iframe。
- 不在 URL 暴露长期 MCSManager 凭证。
- 如果无法安全实现单点登录，就要求用户在 MCSManager 独立登录。
- Agent 执行写任务期间，提示不要在高级管理中同时修改同一实例。

| 流程 | v0.1 优先级 | 研发冻结前置条件 |
|---|---|---|

## 16. 流程验收总则

每一条业务流程至少需要覆盖：

- 正常成功路径。
- 用户取消路径。
- 浏览器断线和恢复路径。
- MCSManager 不可用路径。
- Agent 或模型不可用路径。
